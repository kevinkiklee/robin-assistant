# Robin Runbook

Two parts. **Common operations** is written by hand. **Operational invariants** is generated from the checks `robin doctor` runs (`robin doctor --emit-runbook --write`); fix wording there in the invariant's source under `system/kernel/invariants/builtins/`, not in this file.

Paths below are relative to the user-data directory: `$ROBIN_USER_DATA_DIR` if set, else the path stored in `~/.config/robin/user-data-dir` by `robin init`, else `~/.local/share/robin` (`system/lib/paths.ts`).

## Common operations

**Health.** `robin doctor` checks everything below; `--json` prints a machine-readable report and `--fix` runs the safe repairs. Exit code is 2 when a critical check fails, 1 on warnings, 0 when clean. Open alerts: `robin alerts` (`--all` for history), `robin alerts ack <id>`.

**Daemon.** It runs under launchd as `io.robin-assistant.daemon` (plist in `~/Library/LaunchAgents/`). Restart: `launchctl kickstart -k gui/$(id -u)/io.robin-assistant.daemon`. `robin daemon install` writes and loads the plist; `robin daemon uninstall` unloads and removes it. Stdout and stderr both go to `observability/logs/daemon.log`; the PID is in `state/runtime/daemon.pid`. After `pnpm build`, restart the daemon and reconnect MCP clients, or they keep serving the old build (`mcp.dist_current` below).

**Pause and network.** `robin pause` / `robin resume` stop and restart scheduled work. `robin offline` / `robin online` set `network.mode` in `config/policies.yaml`. `robin incognito [--for=1h|off]` suspends session capture. The power monitor also changes these on its own: battery, Low Power Mode (`power.auto.on_low_power_mode: paused`), quiet hours (`power.auto.quiet_hours`) and metered networks (`network.on_metered`). `robin doctor` shows `(auto: <reason>)` beside a mode it set. A manual change holds until a rule next starts. Metered detection needs the Swift helper at `dist/lib/power-auto/netpath`, which `pnpm build` compiles when Xcode Command Line Tools are installed; without it, metered rules never fire.

**Re-authorize OAuth.** `robin reauth gmail | google_calendar | whoop [--port=N]`. It needs `<PREFIX>_CLIENT_ID` and `<PREFIX>_CLIENT_SECRET` (`GMAIL_`, `GOOGLE_CALENDAR_`, `WHOOP_`) in `config/secrets/.env`, listens on `http://localhost:8089` unless `--port` or `<PREFIX>_REDIRECT_URI` says otherwise, stores the new token, and restarts the daemon if one is running.

**Database.** The database is `state/db/robin.sqlite`.
- `robin db backup [--path=<file>]` checkpoints the WAL and writes a compacted copy (default `robin.sqlite.bak-<timestamp>` beside it). Safe while the daemon runs.
- `robin db restore --from=<file>` copies the backup over the live file. It saves the previous file as `robin.sqlite.replaced-<ms>` and keeps the live OAuth token rows, since a backup's rotating refresh tokens may already be spent. It refuses while any other process has the database open, because that process's WAL would corrupt the restored file: stop the daemon (`robin daemon uninstall`, then `robin daemon install` afterwards) and quit Claude Code sessions using Robin's MCP servers first. The daemon applies any pending migrations when it starts.
- `robin db vacuum` checkpoints and vacuums.
- `robin reindex --force` rebuilds the vector index.

**Auto-land.** The 4:00am reliability audit writes `state/runtime/remediation-request.json`, and a verified fix branch can merge itself (gates in `system/agent/auto-land.ts`). Every land, hold and probation result is appended to `state/runtime/auto-land-log.jsonl`. Kill switch: set `agent.auto_land: false` in `config/policies.yaml`; every branch then waits for review. A land whose build fails, or whose daemon isn't up and settled within 150 s (`system/agent/land-probation.ts`), is reverted automatically. To undo one by hand, `git revert` the merge, `pnpm build`, and restart the daemon.

**File watching fails (EMFILE).** If the log shows `integration watcher failed; hot reload paused` (it retries every 10 minutes), or any `fs.watch` fails with `EMFILE: too many open files, watch`, macOS is out of FSEvents capacity. A common cause is leftover git monitor daemons from a global `core.fsmonitor = true`: every repo git touches gets one, including deleted temp repos, and they never exit. `robin doctor` warns above 200 of them (`git.fsmonitor_bounded` below), and `--fix` or the daily doctor run stops them. Stopping them is safe, since git restarts one on demand. Robin's test script and its agent worktrees turn fsmonitor off so they don't add more.

**Recommendations.** `robin recommendations dedupe` lists duplicate open recommendations; `--apply` supersedes all but the newest.

**Publishing.** Republish, delete, recategorize and thumbnail backfill are `robin publish --mode …`; see `docs/PUBLISHING.md`.

## Operational invariants (auto-generated)

> This section is regenerated by `robin doctor --emit-runbook --write`. Do not edit between the sentinel comments.

### install

#### `install.user_data_writable` (critical)

**Symptom.** Daemon cannot write to user-data/. Integration syncs silently drop; runtime state file fails to update.

**Cause.** user-data/ path is not writable — permissions, full disk, or unmounted volume.

**Fix.** Investigate `df -h` and `ls -la <user-data>`. No auto-repair; needs human attention.

### db

#### `db.reachable` (critical)

**Symptom.** Recall and remember calls fail; scheduler ticks fail.

**Cause.** SQLite connection has been closed or the file is unreadable.

**Fix.** Restart the daemon: `launchctl kickstart -k gui/$(id -u)/io.robin-assistant.daemon`. If the file is corrupt, restore a backup with `robin db restore --from=<path>`.

#### `db.schema_current` (critical)

**Symptom.** Daemon refuses to start with "pending migrations" error.

**Cause.** Package upgrade introduced new schema migrations that have not been applied.

**Fix.** Restart the daemon — it applies pending migrations on startup. Run `robin doctor` to verify.

#### `db.wal_size_bounded` (warning)

**Symptom.** SQLite WAL file grows unboundedly. Reads slow down. Backups take longer.

**Cause.** The WAL is not being checkpointed: a long-lived reader (a stuck MCP server or job) is pinning it, or the daemon is wedged. journal_size_limit only truncates after a checkpoint completes.

**Fix.** Run `robin db vacuum` to checkpoint. If it regrows, find the process holding a read transaction (`lsof` on the DB file) and restart it.

### vec

#### `vec.index_synced` (warning)

**Symptom.** Vector recall returns few/no semantic matches even though content is embedded; recall silently falls back to lexical-only.

**Cause.** events_vec (search index) is out of sync with events_content.embedding — e.g. an embedding-dimension migration, an interrupted reindex, or content embedded by an older path that did not populate the index.

**Fix.** Run `robin reindex --force` to rebuild events_vec from the canonical embeddings.

### integrations

#### `integrations.healthy` (warning)

**Symptom.** One or more integrations are erroring on every tick (e.g. expired OAuth, revoked API key).

**Cause.** consecutive_errors >= 5 for at least one integration in integration_state. Most common: a refresh token has been revoked by the upstream provider.

**Fix.** Run `robin doctor` to see which ones, then re-grant the affected provider (e.g. re-run the OAuth flow via `robin reauth <name>`, paste a new API key into user-data/config/secrets/.env, restart the daemon).

#### `integrations.staleness` (warning)

**Symptom.** A scheduled integration has produced no successful tick in many cadences, or is stuck skipping (e.g. missing secret / revoked OAuth).

**Cause.** last_ok_at is older than warn/critical × the integration cadence, or consecutive_skips >= 3. Common roots: scheduler not firing the tick, expired refresh token, or a missing secret causing every tick to skip.

**Fix.** Run `robin doctor` to see which integrations and why; for OAuth-class skips re-grant with `robin reauth <name>`; for missing secrets add the key to user-data/config/secrets/.env and restart the daemon.

#### `integrations.unreachable` (warning)

**Symptom.** A scheduled integration is stale or skipping because its upstream is unreachable (fetch failed / network error) or transiently failing (5xx/429, upstream back-off).

**Cause.** The machine is offline, DNS or the upstream host is unreachable, a VPN/captive portal is blocking requests, or the upstream is returning transient errors (e.g. whoop cooling off after a gateway failure). Not a local fault — it clears on its own once the upstream recovers.

**Fix.** Check connectivity. If the machine is deliberately offline, set network.mode in policies.yaml so freshness checks are suppressed.

#### `integrations.streams_healthy` (warning)

**Symptom.** One or more integration sub-streams are failing on every tick while the integration itself keeps ticking (e.g. WHOOP workout endpoint returns 503 repeatedly).

**Cause.** A `degraded:<stream>` counter in integration_state has reached 3+ consecutive ticks. The integration tick returns status='ok' overall (partial success) but one data stream is consistently rejected or timing out.

**Fix.** Run `robin doctor` to identify which integration/stream pair is affected. Check the upstream API status for that endpoint. Re-authenticate if auth-scoped (`robin reauth <name>`). If the stream is temporarily unavailable, the counter resets automatically once it recovers.

### jobs

#### `jobs.discoverable` (warning)

**Symptom.** A scheduled job has no loadable code — every fire silently no-ops.

**Cause.** The job's index.ts/index.js or job.yaml was deleted (e.g. mid-restructure) while its cron row in the jobs table remained.

**Fix.** Either restore the missing files under user-data/extensions/jobs/<name>/ (or system/jobs/builtin/<name>/) OR delete the orphan cron row from the jobs table and restart the daemon.

#### `jobs.not_erroring` (warning)

**Symptom.** One or more scheduled jobs have errored within the last 24 hours.

**Cause.** A job handler threw an unhandled exception or timed out; the scheduler marked the row `errored`. Common roots: integration fault, LLM timeout, or a bug in a user job.

**Fix.** Run `robin doctor` to see which jobs are failing; check the daemon log (`user-data/observability/logs/daemon.log`) for the root exception.

#### `jobs.history_bounded` (warning)

**Symptom.** The jobs table grows unboundedly; stale completed/errored rows accumulate and old errors read as current breakage.

**Cause.** Terminal job rows are never deleted (completeJob only flips state; cron re-enqueues each tick). No retention sweep was running.

**Fix.** Run `robin doctor --fix` (the daily doctor auto-prunes terminal rows older than 7 days).

#### `jobs.retries_bounded` (warning)

**Symptom.** A scheduled job retries many times before completing — its lease keeps expiring (slow handler / short lease) or a daemon restart storm keeps orphaning it.

**Cause.** retry_count is bumped only by lease recovery: the run outran leaseMs, or a restart reset a lease held by a dead worker. Repeated bumps mean a chronic overrun or a restart loop, not a one-off.

**Fix.** Read the named job's last_error breadcrumb. "lease expired" → the handler is slower than the lease window (profile it or raise leaseMs); "worker reset" → the daemon is restarting repeatedly (check launchd / crash logs).

### capture

#### `capture.volume_sane` (warning)

**Symptom.** Session captures in the last 24h exceed the sane-volume ceiling.

**Cause.** An automated source is being captured as user sessions: an SDK subprocess missing the ROBIN_INTERNAL_SDK hook guard, a new Robin cognition prompt not covered by the robin_cognition_echo skip rule, or a runaway external claude loop.

**Fix.** Sample recent session.captured bodies for repeated machine-generated shapes; extend the capture skip-rules or hook guard, then purge the junk family (see prune-noise idiom).

### state

#### `state.claude_code_session_bounded` (warning)

**Symptom.** integration_state grows unboundedly: the capture scanner keeps one session-dedup row per transcript file ever seen.

**Cause.** claude_code session:* mtime-dedup rows are only ever upserted, never pruned. 126k rows accrued before a retention sweep existed.

**Fix.** Run `robin doctor --fix` (the daily doctor prunes session-state rows untouched for 14 days).

#### `state.no_orphans` (warning)

**Symptom.** A removed integration still appears in `robin doctor` as a phantom (last synced days ago, looking broken).

**Cause.** Deleting an integration leaves its integration.<name>.tick cron rows and integration_state heartbeat rows behind.

**Fix.** Run `robin doctor --fix` (the daily doctor auto-GCs these). Keyed on on-disk dirs, so a transiently-broken extension keeps its tokens.

### alerts

#### `alerts.history_bounded` (warning)

**Symptom.** The alerts table grows unboundedly; resolved alert rows accumulate and inflate the database without providing operational value.

**Cause.** Resolved alert rows are never deleted (resolveAlert only sets resolved_at; no retention sweep was running).

**Fix.** Run `robin doctor --fix` (the daily doctor auto-prunes resolved alerts older than 30 days).

### beliefs

#### `beliefs.embeddings_bounded` (warning)

**Symptom.** belief_candidates carries embedding blobs on resolved rows, inflating the DB with vectors nothing reads.

**Cause.** Embeddings are attached at draft/dedupe time for pending-row matching, but resolution (promote/reject/merge) never nulled them; every reader is scoped to status='pending'.

**Fix.** Run `robin doctor --fix` (the daily doctor nulls embeddings on promoted/rejected/merged rows).

### recall

#### `recall.history_bounded` (warning)

**Symptom.** recall_log grows unboundedly; years of per-query telemetry inflate the DB long after any replay window needs them.

**Cause.** Every recall (auto + manual) appends a row and nothing ever pruned them; jobs/alerts/session-state got retention sweeps, recall_log did not.

**Fix.** Run `robin doctor --fix` (the daily doctor prunes recall_log rows older than 180 days).

#### `recall.topics_resolvable` (warning)

**Symptom.** Auto-recall references canonical docs that are missing, so a matched topic injects nothing.

**Cause.** A docs path in config/recall-topics.yaml points to a content file that was renamed, deleted, or mistyped.

**Fix.** Correct the path in config/recall-topics.yaml (or restore the doc), then re-run `robin doctor`.

### logs

#### `logs.rotation_bounded` (warning)

**Symptom.** Files under observability/logs/ grow unboundedly; daemon.log reached 91 MB before any rotation existed.

**Cause.** launchd StandardOut/ErrorPath appends forever and no logrotate/newsyslog covers a user-home path; nothing ever cut an archive.

**Fix.** Run `robin doctor --fix` (the daily doctor gzips oversized logs to <name>-<date>.log.gz, truncates in place, and keeps the newest 5 archives).

### daemon

#### `daemon.stable` (warning)

**Symptom.** The daemon has crashed 3+ times within the last hour (crash-loop), or died without a clean shutdown 3+ times within 7 days (something keeps killing it).

**Cause.** launchd is repeatedly respawning a crashing daemon — likely an unhandled startup exception, missing resource, or critical import failure.

**Fix.** Check daemon logs (`user-data/observability/logs/daemon.log`) for the startup error; `launchctl unload` the plist to halt the loop while debugging.

### scheduler

#### `scheduler.progressing` (critical)

**Symptom.** No scheduled job has run for hours: integrations stop syncing and nightly cognition (dream, daily-brief) is silently skipped while the daemon still looks healthy.

**Cause.** Robin is paused (power.state != 'active') and was never resumed — e.g. a manual pause that was forgotten, or an auto-pause that failed to auto-resume — or a job handler is wedged so the single-worker loop never advances.

**Fix.** If paused: `robin resume`. If active: the scheduler loop is stuck on a handler — restart the daemon (`launchctl kickstart -k gui/$(id -u)/io.robin-assistant.daemon`).

### cognition

#### `cognition.no_orphan_children` (warning)

**Symptom.** A cognition child (biographer.run / dream.run) process has been running for over 5 minutes with no current job lease — its lease was reaped as stale while the OS process itself is still alive, a wedged process burning CPU/memory without making progress.

**Cause.** The renewal timer (60s beat) stopped firing while the process itself never exited — most likely a blocking call inside the job handler that never yields back to the event loop, so the unref’d renewal interval never gets a turn to run.

**Fix.** `robin doctor --fix` sends SIGTERM, waits 5s, and escalates to SIGKILL if the process is still alive. The stale lease itself is reclaimed independently by the daemon’s own lease reaper — this only cleans up the leaked OS process.

### agent

#### `agent.worktrees_bounded` (warning)

**Symptom.** Agent worktrees awaiting review accumulate under .worktrees/; each holds a git worktree + branch that consumes disk space and clutters `git worktree list`.

**Cause.** Agentic runs that produced changes leave their worktree in place for human review. Without periodic cleanup they pile up indefinitely.

**Fix.** Review each pending worktree and merge or discard it: `git -C <repoRoot> worktree list`. Remove with `git worktree remove <path> && git branch -D agent/<ts>`.

### git

#### `git.fsmonitor_bounded` (warning)

**Symptom.** File watching fails machine-wide with EMFILE: the integration hot-reload watcher pauses, editors stop noticing changes, and git prints "could not read IPC response".

**Cause.** A global core.fsmonitor leaves a git monitor daemon behind for every repository git touched, deleted temp repos included; together they exhaust macOS FSEvents capacity.

**Fix.** Stop them; git restarts one on demand: `pkill -f "git fsmonitor--daemon run"`. To stop the build-up, turn off the global setting (`git config --global --unset core.fsmonitor`) and enable it per repository instead.

### mcp

#### `mcp.dist_current` (warning)

**Symptom.** A long-lived process (daemon, MCP server) is running compiled code older than what is currently on disk in dist/.

**Cause.** `pnpm build` ran again after this process started and loaded its code; the process is still serving the previous build.

**Fix.** Confirm `dist/` is itself current first (`cat dist/.build-stamp` vs `git rev-parse --short HEAD`) and run `pnpm build` if not — restarting onto a stale dist leaves the process stale. Then restart: `launchctl kickstart -k gui/$(id -u)/io.robin-assistant.daemon` for the daemon, or reconnect the MCP server / client session.
